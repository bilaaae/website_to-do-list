1.2 Struktur Tabel Database MySQL (todolist_db)

Sistem menggunakan 2 tabel yang berelasi logis melalui kolom user_id:

1. Tabel users (Data Akun Pengguna)

  • id (INT, PRIMARY KEY, AUTO_INCREMENT): ID unik pengguna.
  • name (VARCHAR 100): Nama lengkap pengguna.
  • username (VARCHAR 50, UNIQUE): Username untuk login (tidak boleh kembar).
  • email (VARCHAR 100, UNIQUE): Alamat email unik pengguna.
  • password (VARCHAR 255): Hash kata sandi terenkripsi menggunakan algoritma Bcrypt standar industri.
  • created_at (TIMESTAMP): Waktu pendaftaran akun.

2. Tabel tasks (Data Agenda & Tugas)

  • id (INT, PRIMARY KEY, AUTO_INCREMENT): ID unik tugas.
  • user_id (INT, INDEX): ID pemilik tugas (mengisolasi tugas agar tidak terlihat oleh user lain).
  • title (VARCHAR 255): Judul tugas atau agenda.
  • description (TEXT): Rincian catatan tambahan tugas.
  • category (VARCHAR 50): Kategori tugas (Umum, Pekerjaan, Pribadi, Belajar, Keuangan, Kesehatan, Organisasi, UKK).
  • priority (ENUM 'low', 'medium', 'high'): Tingkat kepentingan (Rendah, Sedang, Tinggi).
  • status (ENUM 'todo', 'in_progress', 'completed'): Status kolom Kanban (Belum Mulai, Dalam Proses, Selesai).
  • due_date (DATE): Tanggal batas waktu pengerjaan (YYYY-MM-DD).
  • due_time (TIME): Jam batas waktu deadline pengerjaan (HH:MM:SS).
  • created_at & updated_at (TIMESTAMP): Pencatatan waktu pembuatan dan perubahan otomatis.

⚙️ BAB 2: Bedah Kode config/database.php

File ini adalah jantung backend aplikasi. Di sinilah koneksi, keamanan dasar, dan fungsi pembantu (helper) didefinisikan.

2.1 Logika Koneksi PDO Singleton: getDBConnection()

function getDBConnection() {
    static $pdo = null;
    if ($pdo !== null) {
        return $pdo; // Singleton: cegah pembukaan koneksi berulang kali
    }
    try {
        $dsn = "mysql:host=" . DB_HOST . ";port=" . DB_PORT . ";dbname=" . DB_NAME . ";charset=utf8mb4";
        $pdo = new PDO($dsn, DB_USER, DB_PASS, [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION, // Error dilempar sebagai Exception
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,       // Format hasil query berupa Array Asosiatif
            PDO::ATTR_EMULATE_PREPARES   => false,                  // Prepared Statement Native dari MySQL engine
        ]);
        initDatabaseTables($pdo);
        return $pdo;
    } catch (PDOException $e) { ... }
}
💡 Makna Kondisi & Konsep untuk UKK:
1. static $pdo: Menggunakan Singleton Pattern. Variabel statis tetap hidup selama satu siklus request web. Jika fungsi dipanggil 5 kali di berbagai file, koneksi ke MySQL hanya dibuat 1 kali, menghemat RAM dan resource server.
2. PDO::ATTR_EMULATE_PREPARES => false: Mematikan emulasi PHP. Query dikirim langsung ke MySQL dalam 2 tahap terpisah (persiapan query lalu pengiriman nilai). Ini adalah proteksi anti SQL Injection paling sempurna.

2.2 Logika Penjaga Halaman: requireLogin() & isLoggedIn()

function isLoggedIn() {
    return isset($_SESSION['user_id']) && !empty($_SESSION['user_id']);
}

function requireLogin() {
    if (!isLoggedIn()) {
        setFlash('danger', 'Silakan login terlebih dahulu untuk mengakses aplikasi.');
        header("Location: login.php");
        exit; // Menghentikan eksekusi script seketika agar konten tidak bocor!
    }
}
💡 Makna Kondisi if-else:
- if (!isLoggedIn()): Tanda seru (!) adalah operator logika NOT. Artinya: "Jika pengguna TIDAK sedang login".
- exit;: Sangat krusial! Perintah header("Location: ...") hanya mengirimkan header HTTP redirect ke browser, namun proses PHP di server akan terus berjalan ke baris bawahnya jika tidak dihentikan dengan exit;.

2.3 Logika Sanitasi XSS: e($string)

function e($string) {
    return htmlspecialchars($string ?? '', ENT_QUOTES, 'UTF-8');
}

Makna: Fungsi ini mengubah karakter berbahaya seperti <script> menjadi entitas teks aman &lt;script&gt;. Tag berbahaya tidak akan dijalankan oleh browser korban, sehingga aplikasi 100% aman dari serangan Cross-Site Scripting (XSS).

2.4 Logika Perhitungan Deadline: getDeadlineStatus()

function getDeadlineStatus($dueDate, $dueTime, $isCompleted) {
    if ($isCompleted || empty($dueDate)) {
        return null; // Tugas selesai atau tidak punya deadline, abaikan!
    }

    $now = time(); // Waktu saat ini dalam detik Unix Timestamp
    $timePart = !empty($dueTime) ? $dueTime : '23:59:59';
    $dueTimestamp = strtotime($dueDate . ' ' . $timePart);
    $diffSeconds = $dueTimestamp - $now; // Selisih detik batas waktu

    // 1. Kondisi Terlambat (Waktu sudah lewat dari sekarang)
    if ($diffSeconds < 0) {
        return ['type' => 'overdue', 'label' => 'Terlambat!', ...];
    }

    // 2. Kondisi Mepet (Sisa waktu <= 6 jam = 21.600 detik)
    if ($diffSeconds <= 21600) {
        $hoursLeft = floor($diffSeconds / 3600);
        $minsLeft  = floor(($diffSeconds % 3600) / 60);
        return ['type' => 'super_urgent', 'label' => "Mepet! ($hoursLeft Jam $minsLeft Mnt Lagi)", ...];
    }

    // 3. Kondisi Hari Ini (Sisa waktu <= 24 jam & tanggal sama dengan hari ini)
    if ($diffSeconds <= 86400 && date('Y-m-d', $dueTimestamp) === date('Y-m-d')) {
        return ['type' => 'today', 'label' => 'Hari Ini', ...];
    }

    // 4. Kondisi Besok
    $tomorrow = date('Y-m-d', strtotime('+1 day'));
    if ($dueDate === $tomorrow) {
        return ['type' => 'tomorrow', 'label' => 'Besok', ...];
    }

    return null;
}

3.1 Logika Registrasi & Enkripsi Kata Sandi (case 'register')

// 1. Validasi Input Kosong
if (empty($name) || empty($username) || empty($email) || empty($password)) {
    setFlash('danger', 'Semua kolom formulir pendaftaran wajib diisi!');
    header("Location: register.php"); exit;
}

// 2. Validasi Format Email Menggunakan Filter Bawaan PHP
if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    setFlash('danger', 'Format email tidak valid!');
    header("Location: register.php"); exit;
}

// 3. Validasi Format Username dengan Regular Expression (Regex)
if (!preg_match('/^[a-zA-Z0-9_]{3,30}$/', $username)) {
    setFlash('danger', 'Username hanya boleh huruf, angka, underscore (3-30 karakter)!');
    header("Location: register.php"); exit;
}

// 4. Validasi Kecocokan Konfirmasi Password
if ($password !== $passwordConfirm) {
    setFlash('danger', 'Konfirmasi password tidak cocok dengan password yang dimasukkan!');
    header("Location: register.php"); exit;
}

// 5. Cek Duplikasi Akun di Database
$checkStmt = $pdo->prepare("SELECT id FROM users WHERE username = :u OR email = :e LIMIT 1");
$checkStmt->execute([':u' => $username, ':e' => $email]);
if ($checkStmt->fetch()) {
    setFlash('danger', 'Username atau Email sudah terdaftar!');
    header("Location: register.php"); exit;
}

// 6. Enkripsi Password (Bcrypt Hash Standar Industri)
$hashedPassword = password_hash($password, PASSWORD_DEFAULT);

// 7. Simpan ke Database
$insertStmt = $pdo->prepare("INSERT INTO users (name, username, email, password) VALUES (:n, :u, :e, :p)");
$insertStmt->execute([':n' => $name, ':u' => $username, ':e' => $email, ':p' => $hashedPassword]);
💡 Makna Teknis:
- password_hash(..., PASSWORD_DEFAULT): Menggunakan algoritma pengacakan Bcrypt dengan garam (*salt*) acak otomatis. Password tidak pernah disimpan dalam bentuk teks biasa (plain text), sehingga jika database diretas sekalipun, kata sandi pengguna tidak akan bisa dibaca.
- preg_match('/^[a-zA-Z0-9_]{3,30}$/', $username): Mencegah username mengandung spasi atau simbol berbahaya.

3.2 Logika Login & Verifikasi Kata Sandi (case 'login')

// Cari user berdasarkan username ATAU email
$stmt = $pdo->prepare("SELECT * FROM users WHERE username = :u1 OR email = :u2 LIMIT 1");
$stmt->execute([':u1' => $username, ':u2' => $username]);

}

4.2 Menerima AJAX Drag & Drop Real-Time (case 'update_status')

// 1. Deteksi apakah request berupa JSON dari Fetch API (Drag & Drop)
$isAjax = false;
$rawInput = file_get_contents('php://input');
if (!empty($rawInput)) {
    $jsonData = json_decode($rawInput, true);
    if (json_last_error() === JSON_ERROR_NONE && !empty($jsonData)) {
        $taskId    = (int)($jsonData['id'] ?? 0);
        $newStatus = $jsonData['status'] ?? '';
        $isAjax    = true;
    }
}

// 2. Eksekusi Update Status Khusus Tugas Milik Pengguna Ini
$stmt = $pdo->prepare("UPDATE tasks SET status = :status WHERE id = :id AND user_id = :uid");
$stmt->execute([':status' => $newStatus, ':id' => $taskId, ':uid' => $currentUserId]);

// 3. Jika Request Berasal dari AJAX, Kembalikan Respons Berupa JSON
if ($isAjax) {
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode([
        'success' => true,
        'message' => 'Status tugas berhasil diperbarui secara real-time!',
        'id'      => $taskId,
        'status'  => $newStatus
    ]);
    exit; // Hentikan script, tidak perlu me-redirect halaman!
}
💡 Makna Penting untuk UKK:
- file_get_contents('php://input'): Membaca raw data JSON yang dikirimkan oleh fetch() dari JavaScript.
- header('Content-Type: application/json'): Memberitahu browser bahwa balasan dari server adalah format data JSON murni, bukan dokumen HTML biasa.
- WHERE id = :id AND user_id = :uid: Kunci keamanan tingkat tinggi! Mencegah user lain mengubah data orang lain hanya dengan menebak angka ID.

5.1 HTML5 Drag & Drop & Fetch API: assets/js/dragdrop.js

// 1. Event Ketika Kartu Mulai Digeser (dragstart)
card.addEventListener('dragstart', (e) => {
    draggedCard = card;
    card.classList.add('opacity-50', 'scale-[1.02]'); // Efek transparan saat diangkat
    e.dataTransfer.setData('text/plain', card.dataset.id); // Simpan ID tugas
});

// 2. Event Ketika Kartu Melayang di Atas Kolom (dragover)
zone.addEventListener('dragover', (e) => {
    e.preventDefault(); // WAJIB! Mengizinkan elemen untuk dilepas (drop)
    zone.classList.add('bg-brand-50/50', 'border-brand-400'); // Efek highlight kolom target
});

// 3. Event Ketika Kartu Dilepas ke Kolom Baru (drop)
zone.addEventListener('drop', async (e) => {
    e.preventDefault();
    if (!draggedCard) return;

    const newStatus = zone.dataset.status; // todo, in_progress, atau completed
    const taskId    = draggedCard.dataset.id;

    // A. Pindahkan kartu langsung di DOM layar pengguna (Instan!)
    container.appendChild(draggedCard);

    // B. Kirim pembaruan ke server database via Fetch API (Background AJAX)
    try {
        const response = await fetch('actions.php?action=update_status', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ id: taskId, status: newStatus })
        });
        const result = await response.json();
        if (result.success) {
            updateColumnBadges(); // Perbarui angka jumlah tugas di atas kolom
            showQuickToast('Status tugas berhasil diperbarui! 🚀');
        }
    } catch (error) {
        showQuickToast('Koneksi gagal saat memindahkan tugas!', 'danger');
    }
});

🎯 BAB 6: 12 Pertanyaan Penguji UKK & Kunci Jawaban Jitu

1. Mengapa memilih koneksi PDO dibanding fungsi mysqli_connect()?
Jawaban:
"PDO (PHP Data Objects) memiliki 3 keunggulan utama:
1. Mendukung Prepared Statements Asli secara terstruktur untuk mencegah serangan SQL Injection.
2. Penanganan Error Menggunakan Exception (Try-Catch), sehingga error teknis database tidak bocor ke layar pengguna.
3. Database Abstraction: Jika di masa depan sekolah ingin berganti dari MySQL ke PostgreSQL atau SQLite, kode aplikasi tidak perlu dirombak total."
2. Bagaimana cara kerja sistem keamanan aplikasi Anda dalam mencegah SQL Injection?
Jawaban:
"Aplikasi menerapkan PDO Prepared Statements dengan Named Parameters (contohnya :title, :status, :uid) di seluruh query SQL (seperti pada actions.php). Parameter dikirim terpisah dari struktur perintah SQL, sehingga input berbahaya seperti kutip tunggal (' OR '1'='1) diperlakukan murni sebagai teks biasa dan tidak dapat memanipulasi logika query."
3. Bagaimana cara aplikasi Anda menangkal serangan Cross-Site Scripting (XSS)?
Jawaban:
"Setiap data masukan pengguna yang akan dicetak ke dalam elemen HTML selalu dilewatkan melalui fungsi helper e() di config/database.php, yang membungkus htmlspecialchars(..., ENT_QUOTES, 'UTF-8'). Karakter khusus HTML seperti <, >, dan " diubah menjadi entitas HTML aman (contoh: &lt;script&gt;), sehingga kode JavaScript berbahaya tidak bisa dieksekusi di browser pengunjung."
4. Bagaimana kata sandi pengguna diamankan di dalam database? Apakah pakai MD5?
Jawaban:
"Tidak memakai MD5 atau SHA1 karena kedua algoritma tersebut sudah usang dan rentan dibobol menggunakan Rainbow Table. Aplikasi kami menggunakan fungsi bawaan PHP password_hash($password, PASSWORD_DEFAULT) yang menerapkan algoritma enkripsi Bcrypt dengan garam acak (*salt*) dan beban komputasi dinamis. Untuk memvalidasinya saat login, kami menggunakan password_verify()."
5. Apa fungsi dari klausa 'WHERE user_id = :uid' di setiap query tugas?
Jawaban:
"Fungsinya untuk Data Isolation (Pemisahan Hak Akses Multi-User). Ini menjamin pengguna A tidak bisa melihat, mengedit, atau menghapus data agenda milik pengguna B, meskipun pengguna A mencoba memanipulasi angka ID tugas di URL atau formulir."
6. Apa fungsi e.preventDefault() pada script Drag & Drop?
Jawaban:
"Secara bawaan (*default*), browser web melarang sebuah elemen HTML untuk dijatuhkan (*drop*) ke elemen lain. Memanggil e.preventDefault() di dalam event dragover membatalkan perilaku bawaan browser tersebut sehingga event drop diizinkan berjalan."
7. Apa perbedaan antara Session dan Cookie pada sistem web Anda?
Jawaban:
"Session disimpan di sisi server (aman untuk menyimpan identitas login seperti user_id dan profil akun). Sedangkan Cookie disimpan di sisi browser client (hanya digunakan untuk menyimpan ID sesi unik seperti PHPSESSID untuk menghubungkan browser dengan sesi di server)."
8. Bagaimana alur kerja AJAX saat kartu tugas digeser (Drag & Drop)?
Jawaban:
"1. Pengguna menggeser kartu ke kolom status baru.
2. JavaScript menangkap event drop, lalu memindahkan posisi kartu di layar secara instan (DOM manipulation).
3. JavaScript mengirimkan payload JSON berisi ID tugas dan status baru ke actions.php?action=update_status menggunakan fetch() secara asinkron (*background*).
4. Server MySQL mengupdate kolom status dan membalas dengan status JSON { success: true } tanpa perlu memuat ulang (*refresh*) halaman."
9. Apa itu Singleton Pattern pada koneksi database?
Jawaban:
"Singleton Pattern memastikan bahwa sebuah class atau objek (dalam hal ini objek koneksi PDO) hanya dibuat **tepat satu kali saja** selama siklus hidup satu HTTP request. Variabel static $pdo di getDBConnection() menyimpan objek koneksi pertama. Panggilan berikutnya hanya mengembalikan objek yang sudah ada tanpa membuka socket koneksi baru ke MySQL."
10. Bagaimana cara kerja Flash Message pada aplikasi ini?
Jawaban:
"Flash Message adalah pesan notifikasi sementara yang disimpan di session ($_SESSION['flash']). Saat fungsi getFlash() dipanggil di tampilan, ia mengambil data pesan lalu langsung menjalankan unset($_SESSION['flash']). Dengan cara ini, pesan notifikasi hanya muncul 1 kali dan otomatis hilang saat halaman di-refresh."

🛠️ BAB 7: Kumpulan Tantangan Live-Coding UKK & Solusinya

Penguji sering kali menguji pemahaman siswa dengan meminta perubahan kode secara langsung di tempat (*live-coding*). Berikut adalah kumpulan skenario tantangan paling sering keluar beserta solusinya:

Tantangan Live-Coding 1
"Tolong ubah batas waktu tugas berstatus 'Mepet' dari 6 jam menjadi 3 jam atau 12 jam!"
File yang dibuka: config/database.php (sekitar baris 320)
Cari baris kode: 
if ($diffSeconds <= 21600) { ... }
Ubah menjadi:
  • Jika diminta 3 Jam: ganti angka menjadi 10800 (hasil dari $3 \times 3600$).
  • Jika diminta 12 Jam: ganti angka menjadi 43200 (hasil dari $12 \times 3600$).
Tantangan Live-Coding 2
"Tambahkan validasi: Judul tugas tidak boleh kosong DAN minimal harus 5 karakter!"
File yang dibuka: actions.php (sekitar baris 53)
Cari baris kode: 
if (empty($title)) {
    setFlash('danger', 'Judul tugas wajib diisi!');
    header("Location: index.php"); exit;
}
Ganti dengan: 
if (empty($title) || strlen($title) < 5) {
    setFlash('danger', 'Judul tugas wajib diisi dan minimal 5 karakter!');
    header("Location: index.php"); exit;
}
Tantangan Live-Coding 3
"Tambahkan opsi Kategori baru bernama 'Proyek Sekolah' di formulir Tambah Agenda!"
Langkah 1: Buka includes/modals.php, cari dropdown kategori di formulir tambah tugas.
Langkah 2: Tambahkan baris tag <option> berikut: 
<option value="Proyek Sekolah">Proyek Sekolah</option>
Langkah 3: Buka index.php (baris 32), tambahkan ke array kategori default: 
$categories = ['Umum', 'Pekerjaan', 'Pribadi', 'Belajar', 'Keuangan', 'Kesehatan', 'Organisasi', 'UKK & LSP', 'Proyek Sekolah'];
Tantangan Live-Coding 4
"Tambahkan opsi Pengurutan (Sorting) baru: Urutkan Judul Berdasarkan Abjad A ke Z!"
Langkah 1: Buka index.php (sekitar baris 115), di dalam switch ($currentSort), tambahkan case baru: 
case 'title_asc':
    $sql .= " ORDER BY title ASC";
    break;

"Ubah durasi notifikasi pop-up toast agar hilang lebih cepat (misal dari 4 detik jadi 2 detik)!"

🎤 BAB 8: Strategi Presentasi & Urutan Demo Fitur di Depan Penguji

Kesan pertama sangat menentukan nilai kelulusan UKK. Ikuti alur demo sistem berikut agar seluruh fitur unggulan aplikasi kamu terpamerkan dengan rapi, terstruktur, dan profesional:

📋 Urutan Demo Pengujian Aplikasi:
1. Registrasi Akun Baru: Buka register.php, buat akun baru. Tunjukkan bahwa setelah register berhasil, sistem langsung mengarahkan ke halaman Onboarding Sambutan (welcome.php).

2. Menambah Agenda Baru: Klik tombol "+ Tambah Agenda". Isi judul, kategori, prioritas, tanggal, dan jam deadline. Tunjukkan bahwa validasi bekerja jika judul sengaja dikosongkan.

3. Fitur Drag & Drop (Kanban): Geser kartu tugas dari kolom "Belum Mulai" ke "Dalam Proses" lalu ke "Selesai Dikerjakan". Tunjukkan bahwa badge counter dan persentase progres di atas berubah otomatis secara real-time tanpa reload halaman.

5. Mode Tampilan: Beralih ke mode "Daftar List" (tunjukkan tombol checklist toggle) dan mode "Kalender Agenda" (tunjukkan tanggal agenda yang terplot rapi di kotak tanggal kalender).

6. Logout & Keamanan: Klik tombol Logout, lalu coba tekan tombol "Back" di browser. Tunjukkan bahwa Route Guard (requireLogin()) menolak akses dan mengembalikan pengguna ke halaman login.
